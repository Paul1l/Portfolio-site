# Павел Орехов — портфолио

Продающее одностраничное портфолио frontend-разработчика: коммерческий кейс,
форматы работы, процесс, ответы на вопросы и короткий путь до заявки.

Сайт сделан без сборщика и тяжёлого фреймворка: GitHub Pages получает обычные HTML, CSS и JavaScript-модули. Это осознанный выбор — код можно открыть, прочитать и изменить без установки зависимостей.

## Что есть в проекте

- премиальная адаптивная визуальная система без шаблонного UI-кита;
- коммерческий кейс «МБ Кузбасс» с задачей, решением и результатом;
- сильные проекты из GitHub и отдельный архив ранних работ;
- hash-маршруты кейсов вида `#case/mb-kuzbass`;
- доступные модальные окна на нативном `<dialog>`;
- мобильное меню, scroll-reveal и деликатные pointer-эффекты;
- поддержка `prefers-reduced-motion`;
- AJAX-форма заявки без перехода на страницу посредника и сценарий связи через Telegram;
- FAQ, Open Graph, canonical и Schema.org-разметка проектов;
- статическая разметка карточек: ключевой контент виден поисковикам и без JavaScript.

## Как запустить

ES-модули лучше открывать через локальный сервер:

```bash
python -m http.server 4173
```

После этого сайт будет доступен по адресу:

```text
http://localhost:4173/
```

Можно использовать и любой другой статический сервер.

## Как добавить проект

Откройте `js/projects.js` и добавьте новый объект в массив `projects`.

Основные поля:

- `slug` — адрес внутреннего кейса;
- `title`, `subtitle`, `summary` — тексты карточки;
- `image` и `imageAlt` — локальное превью и его описание;
- `challenge`, `solution`, `result` — содержимое подробного кейса;
- `stack`, `live`, `code` — технологии и ссылки.

Данные из `projects.js` используются в подробных модальных кейсах. Карточку избранного
проекта нужно также добавить в `index.html`, чтобы она оставалась доступной без JavaScript.

## Публикация на GitHub Pages

1. Загрузить содержимое проекта в ветку `main`.
2. Открыть `Settings → Pages`.
3. Выбрать `Deploy from a branch`.
4. Указать ветку `main` и папку `/root`.
